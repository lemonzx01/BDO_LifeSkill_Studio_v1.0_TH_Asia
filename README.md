# BDO Life by BloodMoon TH (Asia)

เว็บคำนวณต้นทุน–กำไร–ROI ของสูตร Life Skill ใน Black Desert Online (เซิร์ฟเวอร์ Asia)

## เริ่มใช้งาน

```bash
npm install
npm run import:data   # ดึงสูตร/ชื่อไอเท็ม/ไอคอน (ครั้งแรก หรือเมื่อมีแพตช์ใหญ่)
npm run dev           # http://localhost:3000
```

ถ้า `.env.local` ตั้ง `DATABASE_URL` เป็นฐานข้อมูล production ไว้ `npm run dev` จะทำงานกับข้อมูลจริง (บัญชี คลังของ สถิติ) · ถ้าจะลองโดยไม่แตะของจริง ดูหัวข้อถัดไป

## ทดสอบบนเครื่องโดยไม่แตะฐานข้อมูลจริง

ตั้ง `DATABASE_URL` เป็นค่าว่าง แล้วให้ PGlite เก็บในโฟลเดอร์ทดสอบแยก:

```bash
# bash / Git Bash
DATABASE_URL="" PGLITE_DATA_DIR=.data/pglite-qa npx next build
DATABASE_URL="" PGLITE_DATA_DIR=.data/pglite-qa npx next start -p 3001   # http://localhost:3001
```

- ได้ผลเพราะ Next ไม่เขียนทับตัวแปรที่มีอยู่แล้วใน environment (แม้เป็นค่าว่าง) จึงไม่โหลด `DATABASE_URL` จาก `.env.local` · ถ้า `.env.local` มี `POSTGRES_URL` หรือ `POSTGRES_PRISMA_URL` ด้วย ต้องตั้งเป็นค่าว่างแบบเดียวกัน
- ใช้ bash ตามตัวอย่าง: ใน Windows PowerShell และ cmd การตั้งค่าว่างเท่ากับลบตัวแปร แล้ว Next จะโหลดค่าจริงจาก `.env.local` แทน
- เช็กก่อนเริ่มว่าเป็นฐานข้อมูลใหม่จริง: เปิด `/setup` ในเบราว์เซอร์ต้องเห็นฟอร์มสร้างแอดมินคนแรก · ถ้าถูกพาไป `/login` แปลว่ายังต่อฐานข้อมูลที่มีผู้ใช้อยู่ ให้หยุดทันที · อย่าดูแค่ status code เพราะ `/setup` ตอบ 200 เสมอแล้วค่อยพาไป `/login` ทีหลัง ถ้าจะเช็กด้วยคำสั่งให้ใช้ `curl -s http://localhost:3001/setup | grep -c NEXT_REDIRECT` ต้องได้ `0`
- เสร็จแล้วลบ `.data/pglite-qa` ทิ้ง (`.data/` อยู่ใน `.gitignore` อยู่แล้ว)

ก่อน push รันให้ผ่านครบ:

```bash
npx tsc --noEmit
npm run lint
npm test        # test ที่ใช้ฐานข้อมูลรันบน PGlite ในหน่วยความจำ ไม่แตะฐานข้อมูลจริง
npm run build
```

การเรียงและตัวกรองบางส่วนของแต่ละหน้าจำไว้ในเบราว์เซอร์ เปิดมาเจอแบบเดิม (ช่องค้นหา และแท็บสายในหน้าคำนวณสูตรไม่จำ) · หัวตารางในหน้าสแกนตลาดและคลังของติดอยู่ใต้หัวเว็บตอนเลื่อนบนจอกว้าง

- **ค้นหาด่วน** กด Ctrl+K (Mac: Cmd+K) หรือปุ่มค้นหา (รูปแว่นขยาย) บนหัวเว็บ จากทุกหน้า · พิมพ์ไม่ถึง 2 ตัวอักษรจะขึ้นลิงก์ไปหน้าต่าง ๆ · พิมพ์ชื่อไอเท็มแล้วแต่ละรายการมีปุ่ม สูตร (เฉพาะของที่มีสูตรทำ) / ตลาด / คิดภาษี · Enter = เปิดสูตร (ไม่มีสูตรจะไปตลาด), Shift+Enter = ดูในตลาด
- **ปักดาว** (ไอคอนดาวท้ายแถว) ในหน้าคำนวณสูตร (ทั้งในรายการและช่องรายละเอียด) หรือสแกนตลาด ของที่ปักจะขึ้นบนหน้าแรกในการ์ด "ของที่ฉันเฝ้า" (การ์ดนี้ขึ้นเมื่อปักไว้อย่างน้อย 1 ชิ้น) พร้อมราคาปัจจุบัน ของค้างขาย กำไรถ้าทำเอง และปุ่มไป ตลาด / สูตร (ปุ่มสูตรขึ้นเฉพาะของที่มีสูตรทำ) · สมาชิก: เก็บกับบัญชี ใช้ได้ทุกเครื่อง · ไม่ล็อกอิน: เก็บในเบราว์เซอร์เครื่องนี้

ทุกหน้าใช้บนมือถือได้: เมนูหลักเป็นแถบแท็บติดล่างจอ 5 ปุ่ม (หน้าแรก / สูตร / ตลาด / คลัง / ภาษี) ส่วน "วิธีใช้" อยู่ในเมนูชื่อ (สมาชิก) หรือปุ่มวิธีใช้บนหัวเว็บ (ไม่ล็อกอิน) · ตารางกลายเป็นการ์ดเรียงลงมา ไม่ต้องเลื่อนทั้งหน้าซ้ายขวา · ในหน้าคำนวณสูตรและสแกนตลาด แถวบนสุดของแถบเครื่องมือ (แท็บ/โหมด + ช่องค้นหา) ติดใต้หัวเว็บ ตัวกรองที่เหลือพับไว้ในปุ่ม "ตัวกรอง" · เพิ่มลงหน้าจอหลักได้ (PWA)

- ไม่ล็อกอิน: หัวเว็บมีปุ่ม **เข้าสู่ระบบ** (ล็อกอินแล้วกลับมาหน้าเดิมผ่าน `?next=` ที่รับเฉพาะ path ในเว็บนี้) และปุ่มตั้งค่าตัวละคร (รูปเฟือง) · หน้าแรกบอกว่า "ใช้ได้เลยไม่ต้องล็อกอิน ข้อมูลของคุณเก็บไว้ในเครื่องนี้" ส่วนคลังของ/ตั้งค่าตัวละคร/แผนผลิต บอกว่า "เก็บไว้ในเครื่องนี้ (ไม่ได้ล็อกอิน)"
- ล็อกอินบนเครื่องที่เคยใช้แบบไม่ล็อกอิน และบัญชียังไม่มีคลังและของที่เฝ้า: จะมีกล่องถามว่า "นำข้อมูลในเครื่องนี้เข้าบัญชี" (ต้องกดยืนยัน) · ข้อมูลในเครื่องจะถูกลบหลังเซิร์ฟเวอร์บันทึกครบทุกรายการเท่านั้น · ถ้าบัญชีมีข้อมูลแล้วจะไม่ถาม
- session หมดอายุ (เบราว์เซอร์ยังส่ง cookie เดิม): หน้าเว็บขึ้นแบบไม่ล็อกอิน พร้อมแถบ "หมดเวลาเข้าสู่ระบบ ข้อมูลในบัญชียังอยู่ครบ" และปุ่ม "ล็อกอินอีกครั้ง" (กด × = ใช้ต่อแบบไม่ล็อกอิน และลบ cookie ที่หมดอายุ) · ถ้าเช็ก session ไม่ได้เพราะฐานข้อมูลล่ม จะขึ้นแถบ "ตรวจสอบการล็อกอินไม่สำเร็จ" แทน
- ออกจากระบบแล้วกลับไปหน้าแรก (ใช้ต่อแบบไม่ล็อกอิน)
- API ที่เปิดสาธารณะ: `GET /api/data`, `/api/prices`, `/api/market/search`, `/api/market/[id]` (ดูการจำกัดในหัวข้อความปลอดภัย), `GET /api/health` และ `POST /api/track` · API ที่ต้องล็อกอิน: `/api/user/*`, `/api/market/refresh`, `/api/perf`, `/api/admin/*`
- เว็บยังตั้ง `noindex` ไว้ (ไม่ให้ search engine เก็บ) ใครมีลิงก์ก็เข้าใช้ได้

## นับจำนวนคนใช้งาน (`/admin/stats`)

แอดมินเปิดได้จากเมนูชื่อ → "สถิติการใช้งาน" หรือปุ่มบนหน้า `/admin`

- **นับอย่างไร:** `UsageBeacon` (ใน `src/app/layout.tsx`) สุ่ม id ให้เบราว์เซอร์ครั้งแรก เก็บใน `localStorage` `bls:vid` แล้วส่ง `{vid, path}` ไป `POST /api/track` ตอนเปิดหน้าและทุกครั้งที่เปลี่ยนหน้า ทั้งคนที่ล็อกอินและไม่ล็อกอิน · **1 เบราว์เซอร์ = 1 คน** (คนเดียวใช้มือถือ+คอม = 2 · ล้างข้อมูลเบราว์เซอร์ = คนใหม่)
- **เก็บอะไร:** แค่ sha256 ของ id, ชื่อหน้า (ไม่เก็บ query string), วันที่ตามเวลาไทย และว่าวันนั้นล็อกอินหรือไม่ · ไม่เก็บ IP ชื่อผู้ใช้ หรือ user id ไว้กับข้อมูลการใช้งาน (IP ใช้แค่ในตัวนับกันสแปมชั่วคราวใน `login_attempts` ซึ่ง cron ลบทิ้งเมื่อหมดช่วงเกิน 1 วัน) · ตาราง `usage_visitor_days`, `usage_visitors`, `usage_page_views`, `usage_capped_days` (เปิด RLS เหมือนทุกตาราง)
- **ไม่นับ:** บอท/crawler/ตัวพรีวิวลิงก์ (user agent ที่ไม่ขึ้นต้นด้วย `Mozilla/` หรือเป็นบอทที่รู้จัก) และเบราว์เซอร์ที่เปิด Do Not Track / Global Privacy Control · คำขอจากเว็บอื่น (Origin ไม่ตรง) ได้ 403
- **กันปั่นยอด:** 120 รายงานต่อที่อยู่ต่อ 15 นาที · คนใหม่ต่อวันได้ไม่เกิน 10 ต่อที่อยู่ (IPv4 หรือ IPv6 /64), 50 ต่อ IPv6 /48 และ 5,000 ทั้งเว็บ เกินแล้วยังนับการเปิดหน้า แต่ไม่นับเป็นคนใหม่ และวันนั้นจะถูกบันทึกใน `usage_capped_days` หน้าสถิติจะขึ้น "บางส่วนไม่ถูกนับ" · หมายเหตุ: ร้านเกม/เครือข่ายมือถือที่หลายคนใช้ IP เดียวกัน อาจนับได้ไม่เกิน 10 คนต่อวันต่อ IP
- **หน้าสถิติแสดง:** คนวันนี้ / 7 วัน / 30 วัน / ทั้งหมด (ตั้งแต่วันแรกที่นับ), คนใหม่ vs กลับมาใช้อีก, สมาชิก vs ผู้เยี่ยมชม, จำนวนครั้งที่เปิดหน้า และหน้าที่เปิดบ่อย, กราฟรายวัน 30/90 วัน และปุ่ม "ดาวน์โหลด CSV" · "คนใหม่" = เห็นครั้งแรกใน 30 วันนี้ ดังนั้นเดือนแรกหลังเปิดนับ "กลับมาใช้อีก" จะเป็น 0 (ดูช่อง "ใช้มากกว่า 1 วัน" แทน)
- ตัวนับ throttle อยู่ใน `login_attempts` และถูกล้างโดย cron รายวัน

## ล็อกอินและสมาชิก

- ตอนยังไม่มีผู้ใช้เลย การกด "เข้าสู่ระบบ" (หรือเปิด `/login`) จะพาไปหน้า `/setup` เพื่อสร้างบัญชี **แอดมินใหญ่คนแรก** (มีได้ครั้งเดียว) · เว็บเปิดสาธารณะแล้ว จึงควรสร้างบัญชีนี้ทันทีหลัง deploy ครั้งแรก
- แอดมินสร้างบัญชีให้สมาชิกที่หน้า `/admin` (ชื่อผู้ใช้ + รหัสผ่านชั่วคราว + สิทธิ์) สมาชิกล็อกอินครั้งแรกจะถูกบังคับตั้งรหัสใหม่
- สิทธิ์ 3 ระดับ: **แอดมินใหญ่** (owner) จัดการได้ทุกบัญชี ตั้งระดับให้ใครก็ได้ และโอนตำแหน่งให้คนอื่นได้ (ตัวเองจะกลายเป็นแอดมินเล็ก) · **แอดมินเล็ก** (admin) สร้าง/ปิด/ลบ/รีเซ็ตรหัสได้เฉพาะสมาชิก · **สมาชิก**
- ปิดใช้งานบัญชี = session ทั้งหมดของคนนั้นถูกยกเลิกทันที เปิดกลับได้ · ลบ = ถาวร · ต้องเหลือแอดมินใหญ่ที่เปิดใช้งานอย่างน้อย 1 คนเสมอ (ระบบเก่าที่มีแต่แอดมิน: คนแรกจะถูกยกเป็นแอดมินใหญ่ให้อัตโนมัติ)
- ฐานข้อมูล: ตั้ง `DATABASE_URL` (Postgres เช่น Neon หรือ Supabase — รับชื่อ `POSTGRES_URL` และ `POSTGRES_PRISMA_URL` ด้วย) ใน `.env.local` หรือ Vercel env · ถ้าไม่ตั้ง จะใช้ **PGlite** (Postgres ฝังตัว) เก็บที่ `.data/pglite` (เปลี่ยนได้ด้วย `PGLITE_DATA_DIR`) สำหรับพัฒนาบนเครื่อง ส่วนบน Vercel ไม่ตั้งจะ error · ตารางถูกสร้างอัตโนมัติ ไม่ต้องรัน migration
- หน้า `/admin` แสดงอายุฐานข้อมูลสูตร และแอดมินใหญ่มีปุ่ม "สำรองข้อมูลทั้งหมด" (บัญชี ตั้งค่า คลังของทุกคน เป็นไฟล์ JSON เดียว)
- รหัสผ่านเก็บแบบ bcrypt, session เป็น cookie httpOnly · ค่าเริ่มต้นหมดอายุ 12 ชม. หรือปิดเบราว์เซอร์ ติ๊ก "จดจำฉันไว้ในเครื่องนี้" ได้ 30 วัน · หน้า "บัญชีของฉัน" มีปุ่มออกจากระบบทุกเครื่อง

## ความปลอดภัย

- ทุกตารางในฐานข้อมูลเปิด Row Level Security และถอนสิทธิ์ของ role `anon`/`authenticated` ของ Supabase อัตโนมัติตอนเริ่มระบบ (เว็บต่อด้วย role เจ้าของตาราง จึงไม่กระทบ) · **ตารางใหม่ทุกตารางต้องเพิ่มใน `APP_TABLES` ใน `src/lib/db/index.ts`** · แนะนำปิด Data API ใน Supabase (Dashboard → Integrations → Data API → ปิดสวิตช์ "Enable Data API" ชื่อเมนูอาจต่างไปตามเวอร์ชันของ Dashboard) เพราะเว็บไม่ได้ใช้
- ตรวจบน production แล้วเมื่อ 2026-10-04: ใช้คีย์สาธารณะ (publishable/anon) ของ Supabase เรียกตารางไหนผ่าน REST API ก็ได้ "permission denied" (42501)
- จำกัดการล็อกอินผิดใน Postgres (`login_attempts`): ต่อชื่อผู้ใช้+ที่อยู่ 10 ครั้ง ต่อที่อยู่ 30 ครั้ง ต่อชื่อผู้ใช้ 50 ครั้ง ใน 15 นาที นับก่อนตรวจรหัสผ่าน · ที่อยู่ที่ล็อกอินบัญชีนั้นสำเร็จภายใน 30 วันไม่โดนนับในเพดานของชื่อผู้ใช้ คนนอกจึงล็อกเจ้าของบัญชีออกจากเครื่องที่ใช้ประจำไม่ได้
- บัญชีที่ยังใช้รหัสชั่วคราวเข้าได้แค่หน้าเปลี่ยนรหัส (เปิดหน้าอื่นจะถูกพากลับมา ส่วน API นับเป็นคนที่ไม่ล็อกอิน) · รหัสใหม่ต้องไม่ซ้ำรหัสเดิม และเปลี่ยนรหัสแล้ว session เดิมทุกเครื่องถูกยกเลิก เครื่องนี้ได้ session ใหม่
- `/api/health` ที่เปิดสาธารณะตอบแค่ `ok`/`db`/`commit` (ต่อฐานข้อมูลไม่ได้จะมี `code` รหัส error สั้น ๆ เช่น `28P01` เพิ่ม ไม่มีข้อความ error) รายละเอียดเห็นเฉพาะแอดมิน · cron ต้องมี `CRON_SECRET` บน production · รีเฟรชตลาดด้วยมือได้ทุก 2 นาที (สมาชิกเท่านั้น)
- API สาธารณะ จำกัดต่อที่อยู่ (IPv6 นับต่อ /64) ต่อ 15 นาที เฉพาะคนที่ไม่ล็อกอิน (`src/lib/public-rate-limit.ts`, ตัวนับใน `login_attempts`, ถ้า DB ล่มนับในหน่วยความจำแทน): `/api/data` ดาวน์โหลดเต็ม 120 ครั้ง (คำขอ 304 ไม่นับ) · `/api/prices` 600 · `/api/market/search` 300 · `/api/market/[id]` 120 · เกินแล้วได้ 429 + `Retry-After`
- คนที่ไม่ล็อกอินไม่เคยทำให้เซิร์ฟเวอร์ยิง API ตลาดเยอะ ๆ: `/api/prices` ตอบจาก snapshot ใน DB เสมอ (ยิง API ตรงเฉพาะตอนยังไม่มี snapshot เลย) · `/api/market/[id]` ที่ต้องถาม API ทางการ ใช้โควตารวมกันทุกคน 300 ครั้ง/15 นาที เกินแล้วได้แค่ประวัติราคาจาก DB · `/market` ไม่ทำ backfill ประวัติให้คนที่ไม่ล็อกอิน · `/api/market/[id]` ตอบเฉพาะไอเท็มที่อยู่ในฐานสูตรหรือ snapshot (อื่น ๆ 404)
- `/api/data` (ข้อมูลสูตรคงที่ต่อ deploy) ส่ง `Cache-Control: public, max-age=0, must-revalidate, s-maxage=31536000` + ETag ให้ CDN ของ Vercel ตอบแทน (Vercel ล้าง cache ทุก deploy) · `/api/prices` ที่ไม่ได้ force ส่ง `s-maxage=60, stale-while-revalidate=300` (ราคาเหมือนกันทุกคน) · ส่วน `force=1` เป็น `no-store`
- Content-Security-Policy พร้อม nonce ต่อ request (`src/proxy.ts`), X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy, ไม่ให้ search engine เก็บหน้าเว็บ

## คลังของและตั้งค่า (`/inventory`)

- สมาชิก: ตั้งค่า (Value Pack, Mastery, รอบ/ชม. ฯลฯ) และคลังของ ผูกกับบัญชี เก็บใน DB ใช้ได้ทุกเครื่อง · ค่าที่เคยบันทึกในเบราว์เซอร์เวอร์ชันก่อนจะถูกย้ายให้อัตโนมัติครั้งแรกที่ล็อกอิน
- สมาชิก: ทุกการแก้ (ตั้งค่า คลังของ ดาว) ส่งขึ้นเซิร์ฟเวอร์ผ่านคิวเดียว (`src/lib/save-queue.ts`) ที่อยู่ข้ามหน้า เปลี่ยนหน้าระหว่างบันทึกก็ไม่หาย ส่งไม่สำเร็จจะลองใหม่เอง · สถานะ (กำลังบันทึก… / บันทึกแล้ว / บันทึกไม่สำเร็จ) ขึ้นบนหัวเว็บ
- ไม่ล็อกอิน: เก็บใน `localStorage` ของเบราว์เซอร์ (`src/lib/guest/`) ตรวจทุกค่าตอนอ่าน ตามการแก้จากแท็บอื่น และเขียนลงเครื่องครั้งเดียวต่อชุดการแก้ (นำเข้า CSV หลายร้อยแถวไม่ค้าง)
- หน้า `/inventory` เพิ่ม/แก้จำนวนและต้นทุนที่จ่ายไป เห็นมูลค่าตลาดปัจจุบัน · ช่อง "มีอยู่แล้ว" ในแผนผลิตใช้ข้อมูลชุดเดียวกัน

## สูตรแปรรูป

- นำเข้าจาก bdocodex (mrecipes): หลอม บด ตากแห้ง เขย่า กรอง ตัดฟืน แปรธาตุอย่างง่าย ทำอาหารอย่างง่าย · ตัดสูตรที่หลอม/บดอุปกรณ์ (อาวุธ/เกราะ/เครื่องประดับ) ออกเพราะไม่ใช่งาน Life Skill
- Mastery แปรรูปในเกมไม่เพิ่มผลผลิตต่อชุด แต่เพิ่มจำนวนชุดที่ทำได้ต่อครั้ง (mass processing) ระบบแสดงตัวเลขนี้ในตั้งค่า ส่วน "รอบ/ชม." ให้กรอกตามความเร็วจริง
- แท็บ "ราชวัง": กล่องอาหาร/แปรธาตุราชวัง ราคาขายคือเงินจาก NPC ส่งของราชวัง (ช่อง "ราคาซื้อ" ในข้อมูลไอเท็ม) × (1 + โบนัส Mastery แปรธาตุ/ทำอาหาร) ไม่หักภาษี ไม่แสดงกำไร/ชม. เพราะมีโควตาต่อวัน
- ยังไม่รวม: สูตรผลิตของกิลด์/อาวุธ

## CSV / มือถือ

- หน้าคำนวณสูตร: ปุ่ม CSV (ไอคอนดาวน์โหลด) ข้างช่องเรียง ส่งออกรายการตามตัวกรองปัจจุบัน · คลังของ: ปุ่ม "นำเข้า / ส่งออก" เปิดแผงที่มี "เลือกไฟล์ CSV", "ส่งออก CSV" และ "ไฟล์ตัวอย่าง" (ไฟล์แม่แบบ) · นำเข้ารับไฟล์ที่ส่งออกไป หรือไฟล์ที่มีคอลัมน์ จำนวน และ id หรือ ชื่อไอเท็ม (จับคู่ชื่อไทย/อังกฤษ)
- นำเข้ามี 2 โหมด: **ทับจำนวนเดิม** (ค่าเริ่มต้น นำเข้าไฟล์เดิมซ้ำได้ไม่ทบยอด) และ **บวกเพิ่มจากที่มี** (แคปคลังในเกมทีละหลัง ทำ CSV ทีละไฟล์ แล้วนำเข้าต่อกันให้ยอดรวมกัน) · ก่อนนำเข้ามีกล่องให้ดูว่าอะไรจะเปลี่ยน และหลังนำเข้ากด "เลิกทำ" ได้
- PWA: มี `manifest.webmanifest` + ไอคอน เปิดในเบราว์เซอร์มือถือแล้ว "เพิ่มไปยังหน้าจอหลัก" ได้ (ยังต้องออนไลน์)

## สแกนตลาด (`/market`)

- เก็บ snapshot ทั้งตลาด Asia (10,000+ ไอเท็ม พร้อมปริมาณซื้อขาย 14 วัน ดึงจาก bdolytics ถ้าล่มใช้ API ทางการแทน) ลง DB: cron รายวันจาก `vercel.json` (ตั้ง `CRON_SECRET` ใน env เพื่อล็อก endpoint) + เมื่อมีคนเปิด `/market` หรือขอ `/api/prices` และ snapshot เก่ากว่า 15 นาที จะรีเฟรชเบื้องหลังหลังส่งคำตอบแล้ว (ถ้ายังไม่มี snapshot เลย `/api/prices` ก็รีเฟรชเบื้องหลังเช่นกัน ส่วน `/market` สร้างให้เสร็จก่อนแสดงหน้า) โดยต้องจองช่องใน `market_meta` ก่อน (`auto_refresh_started_at`) จึงรีเฟรชได้ไม่เกิน 1 ครั้ง/15 นาที ไม่ว่าจะมีคนเข้ากี่คนหรือกี่ server + สมาชิกกด "อัปเดตตลาดตอนนี้" ได้ทุก 2 นาที
- สร้างประวัติราคารายวันของเราเอง และทยอยดึงราคาย้อนหลัง 90 วันจาก API ทางการมาเติม (cron 150 ไอเท็ม/วัน, สมาชิกเปิดหน้า 100 ไอเท็ม/นาที/server) → คอลัมน์ "ราคาปกติ (90 วัน) / เทียบปกติ / กำไรถ้าเทรด" (มี ROI ใต้กำไร) และสัญญาณ "แนะนำวันนี้"
- หน้าคำนวณสูตรใช้ราคาชุดเดียวกันจาก snapshot · สมาชิก: ถ้า snapshot เก่ากว่า 5 นาทีจะยิง API ตรง (cache 5 นาทีต่อ server) · ไม่ล็อกอิน: ใช้ snapshot เสมอ ยิง API ตรงเฉพาะตอนยังไม่มี snapshot เลย

## สูตรที่ใช้

- เงินที่ได้รับจริง = ราคาขาย × 0.65 × (1 + Value Pack 0.30 + Family Fame + แหวนพ่อค้า 0.05)
- ต้นทุนไอเท็ม = ถูกสุดระหว่าง ซื้อตลาด / ซื้อ NPC / ทำเอง (ผลรวมวัตถุดิบ ÷ ผลผลิตเฉลี่ย) โดยเลือกวัตถุดิบทดแทนที่ถูกที่สุดต่อหน่วยให้อัตโนมัติ
- ผลผลิตเฉลี่ยต่อรอบ = (min+max)/2 × (1 − p) + max × p โดย p = โอกาสได้ผลผลิตเต็ม (max) จาก Mastery แปรธาตุ/ทำอาหาร ของแต่ละคน (แปรรูป p = 0)
